# RouteSearch 能力指派枚举 — 验收文档

> 定位：候选生成器**内芯替换**。RouteSearch 的输出契约——合法候选集合
> 的定义、全双工邻接谓词、双预算、见证回退——一字不变；只替换候选
> 的**生成方式**：逐层子集枚举 → 能力指派枚举 + 桥接定向补全 +
> 死路记忆。宪法不动（只在已声明边内找子图，不建边、不改拓扑、
> 不执行工具）。
>
> 来源：docs/routesearch-budget-evaluation.md（2026-10-03 实测评估）
> 与同日方向讨论；本文档起草待用户验收，**验收通过后才开始实现**。

## 1. 背景与动机

现状（评估文档实测，office 域 60 场景）：

- `_enumerate` 以层子集为分支依据（每层 2^n−1 个子集的跨层积），
  而必需能力集只有 3-6 个——以大的一侧为骨架去凑小的一侧；
- 字典序子集生成使截断点任意：246 次预算耗尽事件 / 60 场景，
  候选只有 2-4 条且最小性无保证，"找到哪几条"取决于工具命名；
- 下游放大：candidate_routes → seeds export（静态桥）→ basefast
  种子 → slow 路线 → rank 证据面，候选池窄沿链条传导。

核心观察：任何覆盖路线都存在至少一个**能力指派**（每个必需能力
映射到路线上一个提供者）；office 里每个能力的提供者只有 2-11 个
（变体分化恰好在这一维度）。把分支依据从"层子集"换成"能力指派"，
搜索空间从 Π 2^|Tᵢ| 塌缩到 Π |providers(c)|，且变体多样性
（fast/steady 等）成为枚举的一等产物而非运气。

## 2. 不变量（实现期间一字不得违背）

1. **候选路线定义不变**：span 内逐层非空选择、覆盖必需能力、相邻
   层全双工邻接（`_interconnected` 原样保留为**最终验收谓词**——
   构造路径上考虑过的邻接不得豁免复检）；
2. **可行性与预算解耦不变**：`_max_chain` / `_feasible_witness` /
   `covered_capabilities` / `is_feasible` 一行不动，见证回退机制
   不动；
3. **覆盖判定权归静态 fast 不变**；不建边、不改拓扑、不执行工具；
4. **确定性**：同输入同输出；指派全序化规则（能力字典序 ×
   提供者字典序）写死在实现与测试；
5. **公共 API 签名不变**：`RouteSearch` / `RouteSearcher` /
   `CoverageAnalyzer` 构造参数与方法签名零变更；
6. **既有测试只增不删**。

## 3. 方案

### 3.1 生成器三件套

- **指派枚举**：按全序枚举 `required → provider` 指派（提供者按
  其所在层参与层序约束）；
- **桥接定向补全**：已选内容相邻层出现邻接断点时，在中间层做
  `前向邻居 ∩ 后向邻居` 的定向查找补桥——不提供必需能力的工具
  从"编进所有子集再被支配过滤扔掉"变成"只在需要时被定向找出"；
  补全结果统一过 `_interconnected` 复检；
- **死路记忆（nogood）**：探索失败的 `(层号, 已覆盖集, 前向邻居集)`
  三元组入记；等价状态直接剪。合法性延续只依赖这三样，记忆可靠。

收集阶段沿用现状：支配过滤（真超集淘汰）+ `(工具数, 指纹)` 排序
+ `max_candidate_routes` 上限。

### 3.2 预算语义

- `max_candidate_routes`（结果数上限）语义不变；
- `max_expansions` 计数口径改为"指派/补全检查次数"，定义写入
  docstring；批次 B 依 office 实测定标默认值，保证默认路径不比
  现状更早触顶。

### 3.3 集合等价性的精确表述

完备枚举下（两预算同时放大到耗尽），新旧生成器的最终输出集合
（经同一支配过滤后的反链）必须相等。默认预算下输出**允许不同**
（这正是改进目的），只断言：全部返回路线合法、数量 ≥ 基线、
覆盖判定逐场景一致。

## 4. 批次划分

```text
批次 A  安全网先行（不碰 route_search.py）
        1) 等价性预言机测试：多规模拓扑（2-4 层 × 宽窄层）上，
           双预算放大到耗尽，断言"旧实现 vs 旧实现"可重复；
           为批次 B 预置"新 vs 旧"对照开关（测试内双跑）；
        2) office 现状基线快照：60 场景候选数分布 + 逐场景路线
           指纹，固化为 tests/unit/fixtures/ 下 JSON 工件，
           批次 C 的对照基准；
        3) 覆盖判定解耦断言：默认预算与放大预算下，
           60 场景覆盖判定逐场景一致（不变量 2 的直接证据）。

批次 B  内芯替换（route_search.py 的 _enumerate 及其调用点）
        1) 指派枚举 + 桥接补全 + nogood 记忆实现；
        2) 预算计数口径切换与默认值定标（office 实测留档）；
        3) 等价性预言机切换为"新 vs 旧"双跑全绿；
        4) 既有 RouteSearch / Coverage / fast 回归测试零改动全绿；
        5) 确定性 golden：中规模拓扑上指纹列表全序稳定。

批次 C  office 实证与收尾
        1) 60 场景候选分布 vs 批次 A 基线：覆盖 42-9-9 逐场景
           不变；截断事件数对比留档；变体分化路线计数；
        2) 下游穿透：seeds export 固化数、（可选抽样）slow 路线
           多样性、rank 三 Tier 非空——对照留档；
        3) 文档收尾：评估文档标注落地状态，README/AGENTS §7
           如实更新。
```

依赖：A 必须先行（B 的安全网与对照基准）；B 是唯一的动核批次；
C 只读验证 + 文档。

## 6. 本里程碑不做

```text
k-best DP / 图求解器 / ILP     邻接约束使 DP 状态塌不下去；外部
                               依赖违反确定性纪律（评估文档 C3 维持）
随机采样 / 任何非全序生成       破坏"同输入同输出"
RouteSearcher 门面重构          只有测试消费，维持现状
CoverageAnalyzer 及以上 API     签名零变更，消费方无感
覆盖判定口径 / 见证回退         不变量 2，一行不动
在线侧 / Phase 5-6 任何改动     本里程碑只到 fast 候选池为止
```

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 邻接语义漂移（构造时"已考虑"而跳过复检） | `_interconnected` 作为最终谓词统一复检；预言机集合相等是最硬的捕捉器 |
| 指派最小补全枚举不完备（桥接组合遗漏导致完备枚举下集合不等） | 预言机按拓扑规模梯度覆盖（窄/中/宽层组合）；不等即缺陷即修，不放宽断言 |
| 预算口径变化使默认路径更早触顶 | 批次 B 实测定标，验收含"office 截断事件数不升" |
| 与支配过滤/20 上限的交互引入顺序敏感 | 收集阶段过滤与排序保持同一套、作用于完整发现集；确定性 golden 断言 |
| 下游产物变化引发既有断言波动 | 批次 C 穿透对照；任何下游断言调整须逐条对应到本计划"分布改善"条目，不得顺手弱化 |
